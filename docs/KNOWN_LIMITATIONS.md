# Known limitations

## Not verified

- **Live HarnessRouter execution has never run.** No credentials were available, and no billable call was authorized. The adapter matches the documented contract and passes contract tests built from documented shapes, not recorded traffic. Real-world differences (event payload details, file listing paths, `spend_usd` timing) may need adjustments. This is a separate acceptance gate; see the "Live verification checklist" below.
- Community Edition has not been run against AgentArena.

## Functional scope

- Tasks are **single-file, function-level** problems graded by declarative input/output tests. Multi-file repository tasks ("fix the bug in this Next.js repo without breaking its test suite") are not yet supported. They need repository import, the repository's own test runner in the sandbox, and diff-based artifacts.
- Starter files are sent to agents, but the sandbox only loads the entry file, so solutions cannot import other starter files.
- Supported languages: TypeScript, JavaScript (ESM named export), Python.
- Simulated agents only have solutions for the five built-in tasks. On custom tasks they return a stub that fails every test (labelled in the UI).
- No continuation (`previous_response_id`), background mode or trace ingestion.
- Live updates use 1 s polling, not push.
- Orchestration runs inside the web server process. A server restart marks in-flight runs `interrupted` instead of resuming them, although live provider-side work might have completed.

## Evaluation

- Python static analysis is heuristic (regex). TypeScript/JavaScript analysis uses the TS AST but is not ESLint or a type check against `@types`.
- Quality and security penalties are product choices, not validated metrics. Weights are product defaults.
- Efficiency is relative within one benchmark only.
- Docker isolation shares the host kernel (see SECURITY.md).

## Data

- Demo history is generated by running the real pipeline with simulated agents. With deterministic fixtures, repeated rounds produce near-identical outcomes. That is useful to demonstrate routing mechanics, **but it is not evidence about any real agent.**
- Benchmarks cannot be deleted from the UI.

## Platform

- Developed and verified on Windows 11 with Docker Desktop, Node 24 (engines ≥ 22) and Postgres 16 in Docker.
- Requires Docker for runtime tests. With `SANDBOX_MODE=disabled`, correctness is reported as *unavailable* (never as zero).

## Live verification checklist (to close the live gate)

1. Create a HarnessRouter Workspace API key and two configured agents (for example Codex and Claude Code bases).
2. Set `AGENTARENA_MODE=LIVE`, `ALLOW_LIVE_EXECUTION=true`, `HR_API_KEY=…` in `.env` and restart.
3. Settings → Discover → register both agents.
4. Run one cheap benchmark (the slugify task, 120 s timeout, `max_cost_usd` 0.5) with explicit confirmation.
5. Check: events stream, terminal status, `spend_usd` cost marked provider-reported, artifact retrieved (`PROVIDER_FILE` or `EXTRACTED_FROM_OUTPUT`), evaluation runs.
6. Test cancellation on a second run, and check in the HarnessRouter console that the task stopped.
7. Record the results in TEST_RESULTS.md.
